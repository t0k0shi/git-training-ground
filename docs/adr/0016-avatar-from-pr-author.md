# ADR-0016: アバターはエントリを追加した PR の作成者から取り、表示はニックネーム（name）にする

- **Status**: Accepted
- **Date**: 2026-10-15
- **Supersedes**: [ADR-0013](./0013-check-handle-matches-pr-author.md)（`github` が PR を出した人と同じかの検査）。検査そのものの削除は v6 の T6-03 で行う
- **Related**: [ADR-0007](./0007-use-pull-request-target-for-ai-review.md)、[ADR-0011](./0011-guard-changed-files-on-pull-request-target.md)

## Context

カードと泡のツールチップには `@github の値` を出し、`name` は表示していなかった。PR #73 の参加者は、GitHub のユーザー名が本名に近く、サイトに出るのに抵抗があったため、`github` に別の値（`MissuN.uy`）を入れた。ADR-0013 の検査はこれを失敗にし、Bot は本人のユーザー名を提案した。本人が避けたかったものを、検査が求めていた。

アバターは `github` の値から作っていたので、値を間違えると、壊れた画像や他人のアバターが出る（PR #49 の `Swsafsaij-github-8uhbgv`）。ADR-0013 は、JSON に書かれた値が正しいことを PR のたびに確かめることで、これを防いでいた。

## Decision

- サイトに出す名前は `name`（参加者が決めたニックネーム）だけにする。GitHub のユーザー名は、ページの本文にも HTML（alt など）にも出さない。表示に渡すデータ（`ContributorWithDerived`）から `github` と `handle` を外し、型の上で経路をなくす
- アバターは、エントリを追加した PR の作成者のものにする。公開のビルド（`deploy.yml`）の直前に `scripts/build-avatars.mjs` を動かし、`data/avatars.generated.json`（コミットしない）を書き出す
  - `contributors.json` の履歴を `main` に入った順（`--first-parent`）にたどり、エントリ単位の差分（LCS）で、各エントリを最初に追加したコミットを決める。比べるときは `github` 欄を除く。書き換え（誤字の修正、`github` 欄の削除）では追加者を変えない
  - コミットから、それを含むマージ済みの PR の作成者を API で引く。PR がなければコミットの作成者（`main` に直接 push できるのは管理人だけ）。PR の作成者が Bot、または取れないときは「なし」
  - アバターの URL はアカウントの ID から作る（`https://avatars.githubusercontent.com/u/{id}?s=80`）。ユーザー名を変えても同じ人のアバターが出る
- アバターが「なし」、または画像を読み込めないときは、アバターを出さない（泡は、好きな色の縁の丸に絵文字）。JavaScript が動く前に読み込みに失敗した場合も、描画後に確かめて消す
- 生成ファイルがない（ローカル・PR の CI）、件数が合わない、API が失敗したときも、ビルドは止めず、全員アバターなしで表示する

## Alternatives Considered

| 案 | 理由 |
|---|---|
| **PR の作成者から取る（採用）** | GitHub が記録した事実で、参加者が書き換えられない。JSON に何を書いても他人のアバターにならず、ハンドル名の検査がいらなくなる |
| `github` 欄を残し、表示だけ `name` にする | 本名に近いユーザー名を JSON に書く必要は残る（公開のリポジトリに残る）。入力の手間とつまずき（ハンドル名の間違い、`+2`）も残る |
| 行単位の `git blame` で追加したコミットを決める | 末尾にエントリを足すと、直前の人の `}` や同じ日付の行が差分の上でずれ、直前の人が新しいコミットに付け替えられることがある |
| コミットの作成者だけを見る | コミットの作成者（名前・メールアドレス）は参加者が自由に設定でき、他人になりすませる。PR の作成者を優先し、PR がないコミット（管理人の直接の push）だけで使う |
| ハンドル名の検査を必須から外すだけ | 他人のアバターや壊れた画像を防げない |

## Consequences

- **Positive**: 参加者はニックネームで参加できる。入力の項目が減る（v6 の T6-02 で `github` 欄をなくす）。アバターのなりすましができない
- **Negative**: 公開のビルドが git の全履歴（`fetch-depth: 0`）と GitHub の API に頼る。API が使えないと、その回の公開は全員アバターなしになる（次の公開で戻る）
- **Negative**: これまで「`name` はサイトに出ない」と案内していた。既存の参加者には、表示が変わることを知らせる
- **注意**: ニックネームにしても、GitHub 上の PR と `contributors.json` の履歴には、PR を出したアカウントが残る。チュートリアルで案内する
